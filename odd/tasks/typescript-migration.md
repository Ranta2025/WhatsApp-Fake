# Feature: Migrate the frontend to TypeScript

## Objective
Migrate `frontend/src` (63 files, ~11.5k lines, JS/JSX) to TypeScript with `strict` mode, incrementally,
keeping the app compiling and green after every wave.

## Problem / Why
- User request: "con calma migra todo a typescript, vas a tener más control que con js".
- Today nothing is type-checked; the only `.ts` file (`features/dashboard/types/index.ts`) is unused and its
  `User` type is wrong (assumes lowercase keys; backend returns `Username`/`Telephon` + `avatar_url`).
- The backend contract mixes casings (PascalCase schemas, camelCase call logs and request bodies,
  snake_case avatar/wallpaper fields). Types make that contract explicit and catch mismatches at build time.

## Scope / Authorized
- Tooling: `typescript`, `typescript-eslint`, `tsconfig.json` (strict, allowJs during migration),
  `typecheck` script, build gated on typecheck, ESLint + Vitest for `.ts/.tsx`.
- Domain types generated by hand from `backend/schemas/*.go`, `backend/models/*.go` and WS emitters.
- Rename + type every module, leaf-first, in waves. Behavior-preserving: no feature or backend changes.

## Constraints
- No backend changes (casing inconsistencies are documented in types, not fixed).
- No `any` except at documented third-party boundaries (`unknown` + narrowing preferred).
- Keep `react-refresh/only-export-components` `allowExportNames` for context hooks.
- ~400 authored lines per task is advisory only.

## TDD
- Mode: strict, enabled (source: user global config). Runner: `cd frontend && npm run test` (Vitest, 47 tests at start).
- Migration is a behavior-preserving refactor: existing tests must stay green; `npm run typecheck` is the
  additional gate. New pure helpers introduced while typing get tests first (RED→GREEN).
